# ADR-0004: 組織（テナント）分離をトークンの `org` で強制する

- 状態: Accepted（2026-09-30、ユーザー判断）
- 関連: Issue #106（safety 点検統計の全組織集計）、Issue #114、Issue #46（ユーザー一覧のテナント境界）、ADR-0001
- 適用: 各サービスを 1 PR ずつ `[Approval]` として順次適用する

## 背景

ADR-0001 は「認可は組織（テナント）＋案件（project）＋ロールで行う」と定めている。一方、2026-09-30 の横断調査では、
トークンの `org` で分離を強制しているのは workflow・document・ai（prompts）・construction（WBS）のみだった。
残る約 17 サービスは次のいずれかの状態にある。

- 一覧: クライアントが任意に渡す `organization_id` クエリで絞るだけ、または絞り込みなし
- ID 指定の取得・更新・削除: レコードの組織を照合しない
- 集計: 全組織を集計（safety `/inspections/stats`、security `/dashboard` など）
- 作成: 本文の `organization_id` をそのまま保存（他組織へのデータ注入が可能）

認証済みユーザーであれば、他組織のデータ（erp の請求・支払・原価承認、partner の協力会社・契約など）を閲覧・操作できる。

## 決定

1. **範囲は組織の完全一致とする。** 一般ユーザーは、トークンの `org` と一致する組織のデータだけを扱える。
   組織ツリー（会社→事業部→現場）の配下参照は今回は採らない。必要になった時点で、auth 側でのスコープ付与を
   別の ADR で設計する（Issue #46 の論点はこの決定で「単一組織」として決着）。
2. **`admin` ロールは組織を横断できる。**（2026-09-30 ユーザー判断）
   - 一覧・集計は、`organization_id` を指定しなければ全組織、指定すればその組織が対象になる。
   - 作成時は本文の `organization_id` をそのまま使う。
   - 注意: `admin` トークンが漏えいした場合の影響は全組織に及ぶ。ロール付与の監査を運用で担保する。
3. **fail-closed。** 一般ユーザーのトークンに `org` が無い、または UUID として不正な場合は 403
   （`ORG_REQUIRED` / `ORG_INVALID`）とする。`UUID(int=0)` などへのフォールバックは行わない。
4. **応答の一本化**

   | 操作                                | 他組織を指定・参照した場合                    |
   | ----------------------------------- | --------------------------------------------- |
   | 一覧・集計でクエリに他組織を指定    | 403 `ORG_FORBIDDEN`                           |
   | 作成で本文に他組織を指定            | 403 `ORG_FORBIDDEN`                           |
   | ID 指定の取得・更新・削除・状態遷移 | 404（組織条件付きで検索し、存在を明かさない） |

5. **実装形**（各サービスで同じ形にする）
   - `src/middleware/tenant.py` に `scope_org(user, requested)` と `create_org(user, body_org)` を置く。
     参照実装は safety。
   - サービス層の ID 指定・更新・集計関数は、任意引数 `organization_id` で絞り込む。`None` は admin の全組織参照に限る。
   - 各 PR に、他組織のデータが見えない・作れないことを確かめる否定テストを必須とする。

## 影響

- **正**: ADR-0001 と実装が一致し、組織をまたぐ閲覧・改ざん・注入を防げる。
- **負**: 既存データの `organization_id` がユーザーの `org` と一致しない場合、一般ユーザーの画面からそのデータが見えなくなる。
  例として、partner は `org` が無いトークンで作成すると固定 UUID `...0001` にフォールバックしていた。
  各 PR のマージ前・デプロイ前に、検証環境のデータと利用者の組織が一致しているかを確認する（デプロイは人が実施）。
- **互換性**: 他組織を指定していた API 呼び出しは 403 になる。web の画面（`.tsx`）から `organization_id` を
  明示的に渡している箇所は 0 件だった（2026-09-30 調査）。

## 適用状況

| サービス                                     | 状態                                                                                        |
| -------------------------------------------- | ------------------------------------------------------------------------------------------- |
| workflow / document / ai / construction(WBS) | 既に強制済み（document・ai の `UUID(int=0)` フォールバックは後続で fail-closed に置換予定） |
| safety                                       | 本 ADR と同時に適用（Issue #106）                                                           |
| erp / partner / security / advanced / 他     | 順次適用（Issue #114）                                                                      |

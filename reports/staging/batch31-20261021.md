| 操作 | 可否 | 根拠 |
|---|---|---|
| Zone / DNS レコードの**読み取り** | 可 | `GET /zones` 200 / `GET /zones/{id}/dns_records` 200（112 件） |
| DNS レコードの**作成** | **不可** | `POST /dns_records` → **403 / 10000: needs dns.write** |
| Pages プロジェクト/デプロイの読み取り | **不可** | `GET /pages/projects` → **403 / 10000**（`page.read` 無し） |
| Tunnel / Access の読み取り | 可 | `GET /cfd_tunnel` 200 / `GET /access/apps` 200 |

**結論**: 公開入口の残作業は「資格情報の権限」で止まっている。CEOS の `~/.config/ceos/stg.env` は
本セッションのポリシーで読めず、そのトークンの scopes は**未確認**（推測で埋めない）。

### 2.2 オーナーに必要な操作（この 2 つで公開入口が動き出す）

```bash
# (1) フロントの DNS（Zone → DNS → Edit を持つ資格情報で）
ZONE=e375e651e49a40801a305b89e297bff0
curl -sS -X POST -H "Authorization: Bearer $CLOUDFLARE_API_TOKEN" \
  -H "Content-Type: application/json" \
  "https://api.cloudflare.com/client/v4/zones/$ZONE/dns_records" \
  -d '{"type":"CNAME","name":"construction-os-stg","content":"construction-os-stg.pages.dev","proxied":true,"ttl":1,"comment":"CEOS staging frontend"}'

# (2) Pages の初回 production デプロイ（`page.write` を持つ資格情報で）
#     CI を設置できる場合は .github/workflows/staging-deploy.yml の設置でもよい。

```
